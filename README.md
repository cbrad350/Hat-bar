# Hat Bar Tally 🤠

A phone-first register for a custom hat bar, styled after the printed menu and linked
to the shop's **Square** account. Build the hat top-to-bottom with the customer —
hat, bands, feathers, details — then take payment through Square Point of Sale.

## The guided flow

Sections open one at a time, like folders:

1. **Hats** (pick one) — tap the section, a dropdown shows every hat with its photo
   and price ($185 / $225 tiers). Picking one selects it and auto-scrolls to the
   next section. The section header always shows what's on the order.
   A banner reminds the customer every hat includes *3 signature bands, 3 feathers,
   1 small pin, 1 burnt-in brand* (editable list).
2. **Hat Upgrades / Bands / Feathers / Details** (mix & match) — +/− steppers per
   item, photos and prices from the Square library, **Next section ↓** to keep moving.
3. **Discount** — a code box at the bottom. Codes are defined in Edit Menu
   (percent or dollar amount) and show on the receipt as a named discount line.

Enhancements charge **full list price** — swaps and extras only ever add; skipping an
included item never deducts. Items priced like **$15+** ask for the exact amount when
added. The pinned bar shows the running total with a tap-to-expand itemized receipt,
**New Hat** (with Undo) resets for the next customer, and **Charge** sends the final
(discounted) total to Square.

## Linking the Square account

Two connections, neither of which ever exposes an account secret in the app:

### 1. Items & photos, pulled from the Square catalog

The repo has a **Sync Square catalog** GitHub Action
(`.github/workflows/sync-square.yml`) that calls Square's Catalog API with an access
token stored as a **repository secret**, downloads every item, price, category, and
product photo, and commits them as `square-catalog.json` + `square-photos/`. The app
then imports that with one tap.

One-time setup:

1. At [developer.squareup.com](https://developer.squareup.com) open (or create) the
   application and copy its **production Access Token**.
2. In this repo: **Settings → Secrets and variables → Actions → New repository
   secret**, name `SQUARE_ACCESS_TOKEN`, paste the token.
3. **Actions tab → Sync Square catalog → Run workflow.** (It also refreshes weekly.)
4. On the phone: **Edit Menu → Square → ⟳ Import items & photos from Square.**

The importer maps the **HAT** category to the pick-one Hats section (anything named
"…Upgrade" splits into Hat Upgrades), and BANDS / FEATHERS / DETAILS become mix &
match sections — category prefixes like "BANDS: " are stripped from names. Re-run the
action + re-import any time the Square library changes.

### 2. Payments, through the Square POS app

**Charge** uses Square's [Point of Sale API](https://developer.squareup.com/docs/pos-api/what-it-does)
app-switch: it opens the Square POS app with the exact total and an itemized note,
payment is taken there (tap-to-pay, reader, cash…), and the sale lands in the Square
account. Setup: install Square POS on the phone, sign in, and paste the same Square
application's **Application ID** (`sq0idp-…`, not the secret token) into
**Edit Menu → Square**.

## Branding

**Edit Menu → The Shop**: add the **logo** from the camera roll (shown in the
masthead), plus shop name and tagline. Every menu item can carry a photo — synced
from Square or attached from the camera roll (tap the item's circle in Edit Menu).

## Putting it on an iPhone

1. Enable **GitHub Pages**: repo **Settings → Pages**, *Source* → **GitHub
   Actions**. The `Deploy to GitHub Pages` workflow then publishes the site on
   every push to `main` (and after each catalog sync), live at
   `https://<username>.github.io/Hat-bar/`.
   *Private repos need a paid GitHub plan (Pro or above) for Pages; public repos
   are free. Pages cannot be switched on from a workflow — this click is
   one-time and unavoidable.*
2. Open that URL in **Safari** → **Share → Add to Home Screen**.

It launches full-screen from its own icon and works offline (the synced catalog and
photos are cached after first load). Menu edits, the logo, discount codes, and the
Square ID live in that phone's storage — set up on the phone used at the bar.

## Development

No build step — a static page. `python3 -m http.server 8000` and open
`http://localhost:8000`.

| File | Purpose |
| --- | --- |
| `index.html` | The whole app: UI, styles, flow/tally/discount/photo/Square logic |
| `scripts/sync-square.js` | Catalog sync run by the Action (token via env, server-side only) |
| `.github/workflows/sync-square.yml` | The **Sync Square catalog** action |
| `square-catalog.json`, `square-photos/` | Generated by the sync — don't edit by hand |
| `sw.js` | Offline caching (synced catalog is network-first; bump `CACHE_VERSION` on app changes) |
| `manifest.json`, `icons/` | PWA install metadata |
